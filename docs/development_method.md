## 開発手順

1. 要件定義
  - 何を作るのか
  - 誰に作るのか
  - 何のために作るのか
  上記を明確にして、開発に取り組む

  - 始めはMVPで決定する
  - UMLによる設計（クラス図やシーケンス図を用いる）
  - [要件定義の参考](https://qiita.com/syantien/items/9a8a7cbaeca2be3ef0d7#3-%E6%A9%9F%E8%83%BD%E8%A6%81%E4%BB%B6)

2.　クラス図・シーケンス図を作成
  - クラスの構築内容を定義
  - アプリケーションの遷移を定義

3. タスクを分解する
  - Issueを起こして、何のテストを書いていけばいいかや、何をすればいいのかを設定
    - 粒度は細かく
  - [タスク管理の参考](https://qiita.com/ham0215/items/057144589edf3374acc4)

4. Docker環境セットアップ
  - 開発環境、CI環境、デプロイ環境を統一するためにセットアップする

5. GitHub Actions設定
  - リンター、フォーマッターの設定
    - Ruffなどを導入し、自動で確認されるようにする
  - CIの設定
    - Docker環境上で動くようにセットアップする
    - テスト、カバレッジを自動で測定、レポート出力するようにする
  - CDの設定(また今度。できれば)

6. TDD
  - RED → GREEN → REFACTORING の順で細かく開発を進める
  - フォルダ構造、API設計、データベース設計についても事細かに考えること
    - 記事やリファレンスを参照して、がんばれ
